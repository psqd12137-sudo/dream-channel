# Channel Godot 下一阶段执行计划

更新时间：2026-08-13。依据最新版 Web README、当前 Godot 实现和本轮视觉/交互验收整理。

## 本轮已完成的前置修复

- 战斗地形改为固定语义色：浅灰 `H0`、中灰 `H1`、深灰 `H2`，墙与柱为绿色；战斗使用中性灯光，避免灰阶被青色环境光污染。
- 传送门使用紫色成对圆环。玩家踏进入口后停在入口，由右栏选择“穿过”或“留在这里”；出口被怪物占用时禁止重叠。
- 盖屋阶段在扩建格内显示所选房间预览；按“旋转 90°”会立即旋转地图中的房间、门位和合法性提示。

## P0：战斗节奏差异化

目标：同一张图和不同怪物不能继续表现为“每回合沿最短路走几格”。

### P0.1 意图时间轴

- 将当前单层 `path + hurt` 扩展为分拍意图：`windup`（蓄力）、`move`（移动）、`attack`（攻击）、`recover`（收势）。
- 地图直接显示每一拍：蓝色移动编号、红色攻击区域、红色虚线蓄力区域，以及攻击发生在第几拍。
- 敌人回合严格按同一时间轴播放，预测与结果只使用一份数据。

验收：长廊射手至少出现“换线/蓄力/整线攻击”三种节奏；玩家能在出手前一回合看懂红线并躲开。

### P0.2 四类基础怪物行为

1. 追击型：持续靠近，破韧后产生额外停顿。
2. 保距型：距离过近先撤退，再蓄力直线攻击；用于长廊。
3. 连击型：一次意图显示两段落点和每段伤害；用于阁楼/地窖。
4. 伏击型：借墙和视野移动，失去视野时搜索最后目击点，再重新选伏击位。

验收：四类怪物在相同地图、相同玩家位置下生成明显不同的前两回合行动时间轴。

### P0.3 高低差规则补全

- 攀爬 `H0→H1`、`H1→H2` 额外消耗行动力；下降不额外收费。
- 高打低和高台藏匿按 Web README 的规则进入伤害/视野计算。
- UI 在可移动格上直接显示实际 AP 花费，如 `走 2AP`。

验收：同一终点的平路与攀爬路线产生不同 AP；胶靴遗物能免除攀爬附加消耗。

## P1：每个地图的固定微缩模型

目标：战斗数据仍由 `arena` 决定，但每个房间拥有一套可辨认的舞台模型，不再只有格子、墙和高台。

### 结构

- 新增 `ArenaVisualRegistry`：以房间 ID 映射到独立 `.tscn` 微缩模型。
- 每个模型只负责地板外观、家具、墙柱造型、灯光点和环境动画；格子坐标、碰撞和规则仍由 `CombatRules` 管理。
- 用命名锚点绑定规则对象：`Cell_2_3`、`Wall_1_4`、`Portal_A`、`Portal_B`，防止视觉模型改变规则位置。
- 未制作专属模型的房间继续使用当前灰阶程序化棋盘作为 fallback。

### 首批四张示范图

1. 长廊：灯管、错层平台、柜体遮挡、尽头射线轨道。
2. 西厢：转角柜子、上下两条绕行路线、嗡鸣门。
3. 地窖：石柱、盐痕、水面/潮气、较重的遮挡。
4. 会客室：桌椅、电视雪花、八数码事件道具，为事件房接入做准备。

验收：隐藏 UI 后，仅看模型截图也能辨认四个房间；模型不得改变格子点击、路径和视野测试结果。

## P2：空间连击与传送门深化

- 传送门确认加入出口预览：悬停“穿过”时，高亮出口和预计剩余 AP。
- 敌人仍按公开意图自动穿门；蓝色路径同时标出入口、出口和传送编号，不让中间位移像瞬移 bug。
- 实现 Web README 已定义的空间连击：盐道、闪瞎、夹击、纸影、追击踩踏、高台砸击、隧道。
- 结算日志和地图浮字同时说明触发来源、伤害、韧性与奖励，避免只在后台生效。

验收：至少三种空间连击能从摆牌 → 走位 → 敌人踩中 → 地图反馈完整演示。

## P3：事件房接入主循环

- 把现有八数码拼图接入会客室，把打字追逐 QTE 接入泥靴间，把 3D 搜物接入一间静室/事件房。
- 三种小游戏统一返回 `EventResult`：成功/失败、耗时、奖励、受伤或恢复。
- 按 README 的目标比例调整种子分配：惊吓约 40%、静室约 35%、事件约 25%。小游戏只承担节拍调剂，不替代战斗。

验收：从盖屋、进入房间、完成小游戏到奖励/受伤和行程推进，全程不需要主页测试入口。

## P4：局内成长和节目闭环

- 战后卡牌奖励二选一、静室恢复、低血撤退。
- 10 房后进入祭坛 Boss；实现锚点/血条双胜利、播出进度失败和公开节目指令。
- 增加继续游戏、音乐开关、实验数据导出；随后再评估回火房/升级、杂影双敌和商店货币。

验收：能从主页完整完成或失败一局，不依赖测试台；Boss 的每种失败/胜利条件都有明确地图与 HUD 反馈。

## 推荐实施顺序

先完成 `P0.1 → P0.2 → P1 长廊示范图`，用一张地图证明“规则节奏 + 固定模型 + 意图演出”能协同工作；确认美术和玩法方向后，再批量制作其余房间。接着完成 `P0.3/P2`，最后把现有小游戏接入主循环。这样能避免先做二十多张模型后又因战斗规则改变而返工。

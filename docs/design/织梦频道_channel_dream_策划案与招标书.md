## 0. 一句话与电梯稿

**一句话**  
玩家带着官方角色或自己的 OC 拧开一台邪典儿童节目的电视机，成为会失控的微缩玩具秀演员：在会咬人的纸盒布景里用**放置道具 + 走位拉扯**打怪；每局经历都会成为角色记得、讲得出来的一集节目。

**电梯稿（30 秒）**  
channel 不是温馨合家欢，也不是马里奥派对。它是一档用纸盒、黏土、毛毡和涂漆玩具搭出来的怀旧儿童秀，节目运行时逐渐暴露失控的超现实内核（气质接近 *Superjail*）。单人玩法借用探屋、构筑与空间战斗结构，但玩家看到的始终是节目舞台，而不是对《山屋惊魂》的视觉复刻。OC 是这档节目的演员：玩家控制 TA 在布景中探索和战斗，AI 只在局后把真实经历转成回顾、后台日常与长期记忆。多人吃的是「分头 → 尖叫 → 合流」与「半场改剧本」。我们先做透**一集单机节目 + 一个记得这集的角色**，再谈联机。

## 1. 产品定位

### 1.1 我们是什么

| 维度 | 定义 |
| --- | --- |
| 品类 | 邪典荒诞儿童玩具秀题材的 **空间构筑 roguelike / 节目流程游戏** |
| 单机核心 | 房间探索 + **放置 × 走位** 遭遇战 + 牌库成长 + 仪式感 Boss |
| 角色层 | 官方角色或玩家 OC 作为「节目演员」；局后形成回顾、关系与记忆 |
| 产品结构 | **肉鸽玩法是主干，AI OC 是局外情感与叙事层**；两者共享同一角色、事件日志和频道包装 |
| 多人愿景 | 合作探索节目布景 → 半场不对称（改剧本者）→ 整图终局分工 |
| 美学 | **怀旧 · 邪典 · 荒诞**；儿童节目外壳 + 失控内核 |
| 情绪 | 好笑、发毛、窘迫、被节目收看；失败可以是「被播映」 |

### 1.2 我们不是什么（硬否决）

| 明确不做（主线） | 原因 |
| --- | --- |
| 马里奥派对合集 | 小玩法只作节拍器，禁止「每房一个玩具」 |
| 狼人杀 / 开局隐身份投票局 | 奸徒是**半场改剧本**，靠空间害人，不靠嘴炮验人 |
| 纯站桩数值卡牌 | 移动与放置是战斗身份 |
| 第二套养成/成长轴（小游戏数值） | 小游戏不替代主构筑 |
| 一上来做完整联机运营 | 先单机一集验证节目感 |
| 独立的 AI 陪伴/聊天 App | AI OC 必须消费肉鸽真实经历，不能再分裂成另一款产品 |
| AI 裁定战斗、奖励或存档事实 | 玩法结果必须由确定性规则产生，AI 只负责演绎和表达 |

### 1.3 参照系（只借气质/结构，不抄系统）

| 参照 | 借什么 |
| --- | --- |
| 山屋惊魂 Betrayal | 探屋、预兆、半场奸徒、拖怪+破机关 |
| 杀戮尖塔 | 一局构筑、节点节奏、失败重来 |
| 致命公司 | 分头、听惨叫、看见队友窘迫 |
| 博德之门 3 | 战斗检测范围、脱战后即时探索 |
| Superjail | 儿童节目壳 + 荒诞暴力美学张力 |
| 路易吉鬼屋 / DQ7 重置 | 微缩模型感、景深、盒中景 |
| Virtual Cottage 2 | 宜居的微缩空间密度、家具交互和角色自然占位；不借生产力产品定位与纯温馨家居主题 |
| 金山打字（年代玩具） | 短、憨、好懂的跟键感——**克制使用**；联机抓小偷仅作 PvP 旁支 |

《山屋惊魂》只描述探屋、预兆和半场规则变化等玩法来源，不能作为项目名、美术主题或对外品类名。`Virtual Cottage 2` 只用于研究微缩房间为何宜居、角色为何愿意停留；最终资产必须经过《织梦频道》的玩具秀材质、节目装置和荒诞状态转换，不能直接收敛成温馨住宅。

## 2. 体验支柱（设计验收用）

任何功能上线前问这六句；答不上来就砍或降级。

1. **节目感**：这像不像「频道里播出的一集」，而不只是规则表？  
2. **空间感**：玩家是否在用房间、墙、视线、高低思考，而不是只算 DPS？  
3. **反站桩**：移动与放置是否比正面硬刚更优？  
4. **克制**：是否在堆派对玩具或验人玩法？  
5. **可惨不死**：事件失败是否多为丢奖励/小代价，而不是无意义劝退？（战斗失败可终局）
6. **角色记得**：本局是否留下了可回顾的角色经历，而不是打完即清零？

## 3. 单机主循环（当前已实现骨架）

### 3.1 一局结构

```text
行前预兆二选一
  → 雾图探索（约 10 房行程）
  → 惊吓房：放置×走位战斗 / 静室：成长或考验
  → 祭坛 Boss（仪式双轨）
  → 通关或被播映/战死
```

### 3.2 战斗身份（不可动摇）

- **出牌 = 往场地放物品**（地刺、盐圈、闪光等）或打出即时技巧/药物  
- **移动**迫使敌人把行动力花在追击上  
- **韧性**：走位引怪踩机关削韧 → 破韧分型奖励 → 再输出  
- **意图看格子**：红区伤害、蓝虚线移动；玩家不靠长句心算  
- 地形：墙挡视线、高低差、传送格、埋伏、突脸  

细则见仓库：`cabin-slice/data/run-scheme.md`、`cards-rules.md`、`pressure.json`。

### 3.3 成长

- **主轴：牌库**（战斗胜利加牌）  
- **跳变：遗物节点**（开局二选一、中点保底）  
- **辅：静室小数值**（速度权重低）  
- 不做局外长养成阻塞一局体验  

### 3.4 节奏目标混合（可调）

| 类型 | 约占比 | 作用 |
| --- | --- | --- |
| 惊吓战斗 | 40% | 主循环 |
| 静室数值/预兆 | 35% | 喘息与成长 |
| 解密·视角事件 | 25% | Haunt 式考验，调剂操作通道 |

当前问题：静室多为弹窗二选一——**配比已靠 40/35/25 落地，下一期继续打磨静室呈现与 Boss 曲线。**

### 3.5 事件考验（克制）

原则：短、好懂、有趣；允许年代记忆玩具感；**全图少量挂载**。

| 类型 | 状态 | 说明 |
| --- | --- | --- |
| QTE 跟键 | 已接占位（泥靴间） | 有金山打字憨感；失败丢奖励，血>1 可 −1 |
| 八数码拼图 | 未做 | 滑块还原，限步/限时 |
| 第二视角搜物 | 未做（仅临时 2D WASD 沙盒） | **最终：3D 微缩景深**，非扁横版平台跳 |
| 打字追逐 PvP | 愿景旁支 | 不进节目主线 |

## 4. AI OC：节目演员与局外记忆层

### 4.1 功能定位

AI OC 不是第二套主玩法，而是把一局肉鸽从「一次规则结算」变成「这个角色亲历的一集节目」。

| 对象 | 权限与职责 |
| --- | --- |
| 玩家 | 创建/选择 OC，决定核心设定，在战斗和探索中直接操作角色 |
| 确定性游戏系统 | 决定地图、行动、伤害、奖励、胜负与存档，是事实唯一来源 |
| AI 演员层 | 根据事实日志生成角色口吻、局后回顾、后台日常和记忆呼应 |
| OC | 既是局内可控角色，也是局外会回忆、评论并被经历塑造的节目演员 |

当前竖切片先使用官方角色 **Lili** 验证整条链路；自建 OC、导入角色卡和多 OC 关系不进入首个 MVP。

### 4.2 合并后的完整循环

```text
选择官方角色 / OC
  → 进入节目式空间构筑肉鸽（玩家直接操作，规则确定性结算）
  → 记录房间、受伤、连击、遗物、Boss、胜负等事实
  → 生成「本集回顾」与角色短评
  → 关键事实沉淀为角色记忆
  → 后台 / 离线生活片段引用这些记忆
  → 下一局在台词、反应和节目包装中形成呼应
```

AI 内容必须依赖真实局内事件。没有发生过的胜利、同伴、道具或关系变化不得被生成器补写。

### 4.3 首期功能

| 功能 | 首期口径 | 明确不做 |
| --- | --- | --- |
| 本集回顾 | 用现有 `cabin-lab-v1` 与事件日志生成 3～6 句节目摘要 | 自由编造另一段冒险 |
| 角色短评 | Lili 以稳定人设评论本局高光、失误或失败 | 无限制聊天 |
| 记忆碎片 | 每局提取 1～3 条结构化记忆，可由玩家标记重要 | 把完整聊天记录全部塞进上下文 |
| 后台日常 | 离线期间最多积累 3 条、每条 2～4 句，只延续最近节目余波 | 离线推进主线、发奖励或改变战斗状态 |
| 情绪表现 | 先使用人工精选的预设情绪立绘和短动画 | 每段文本实时生图 |
| 回顾空间 | 按节目期数查看事实、回顾文本和角色记忆 | 删除玩家可见的历史记录 |

### 4.4 记忆规则

| 层级 | 内容 | 衰减规则 |
| --- | --- | --- |
| 核心设定 | 名称、外观、性格底色、背景、禁止行为 | 永不由 AI 修改 |
| 重要记忆 | 首次通关、关键 Boss、玩家手动标记事件 | 长期保留并可导出 |
| 经历记忆 | 普通房间、受伤、卡牌连击、节目事故 | 检索权重随时间与引用次数下降 |
| 回顾档案 | 每局完整事实日志与已生成回顾 | 玩家始终可查看；不因 AI「遗忘」而删除 |

「记忆的自然死亡」只表示旧经历逐渐不再进入 AI 上下文，不表示篡改存档或向玩家收费赎回记忆。角色可以遗忘细节，项目不能删除玩家的历史。

### 4.5 AI 边界与质量门槛

1. **规则不交给 AI**：战斗、地图、奖励、数值、胜负和成就只读游戏状态。
2. **玩家拥有角色**：核心设定不可擅改；角色资料、重要记忆和回顾支持导出。
3. **事实先于文采**：生成前传入结构化事件，生成后校验角色名、Boss、结果和关键数值。
4. **失败可降级**：超时、限流、审核失败时使用模板回顾，不阻塞结算和开下一局。
5. **内容要克制**：检测 OOC、事实矛盾、近期开场/情绪/措辞重复；最多重试两次。
6. **隐私默认最小化**：首期不读取通讯录、日历、健康数据，不向外部聊天软件主动发消息。

首期采用一条可观测流水线，不为“多 Agent”而拆 Agent：

```text
确定性事件日志
  → 回顾生成器
  → 人设 / 事实 / 重复 / 安全校验
  → 结构化记忆提取
  → 回顾空间与后续检索
```

### 4.6 分期

| 阶段 | 交付 |
| --- | --- |
| A：网页验证 | Lili 固定人设；本集回顾；1～3 条记忆；模板降级；不做运行时生图 |
| B：单机样片 | 回顾空间；后台日常；情绪立绘；本地/云端模型适配；角色数据导出 |
| C：内容扩写 | 自建 OC、微习惯、CCv2 导入导出、多角色槽位 |
| D：多人之后 | 队友共同记忆、分头经历拼接、奸徒事件的有限视角回顾 |

**验收**：回顾不得与战局事实矛盾；陌生玩家能从语气辨认 Lili；下一局能自然引用旧经历；关闭 AI 服务后肉鸽仍可完整游玩。

## 5. 美学与视听规格

### 5.1 视觉

- **关键词**：黏土/毡质角色、玩具屋、浅景深、盒中景、CRT/儿童节目包装  
- **第二视角/展示房**：3D 微缩 + 景深（路易吉鬼屋 / DQ7 重置向）  
- **UI**：可保留「节目单/票根/嘴巴电视机」等邪典儿童节目符号（现网页已有雏形）  
- **房屋身份**：可构建房屋是儿童节目摄影棚中的实体微缩布景；允许露出胶带、接缝、支架、轮子、场记标和假透视
- **禁止**：默认紫渐变赛博无风格堆砌；把 channel 做成通用黑暗魂 UI、传统地牢或纯温馨住宅

#### 5.1.1 房间资产与角色占位锁

房间首先要让人相信角色可以生活和互动，其次必须让人意识到这是一套正在播出的玩具秀布景。每个房间的表现层按以下结构验收：

| 层 | 规则 |
| --- | --- |
| 宜居主体 | 床、桌、椅、柜、炉具等建立明确房型；借鉴 `Virtual Cottage 2` 的构图密度，不复制其主题 |
| 节目证据 | 每房至少一处场记板、走位胶带、摄影灯、提词卡、假窗、布景支架或可见机关 |
| 荒诞破口 | 每房保留一处可被事件激活的错误比例、重复道具、异常动作、串台声画或不合时宜文案 |
| 制造语言 | 纸板高粗糙度，黏土/毛毡保留手作起伏，涂漆木件允许磨损；避免写实 PBR 豪宅和通用地牢石材成为主印象 |
| 演员走位点 | 一个逻辑格可拥有多个家具交互槽；坐、靠、翻找、表演、躲藏分别占槽，多人不得争用同一槽 |
| PCG 边界 | 家具和节目装置属于表现层，不改门洞、连接边、寻路和战斗账本；门、楼梯、开放通道与建造接口必须保留净空 |

房间应支持“正常播出”和“节目失控”两个表现状态。失控通过灯光、动画、字幕、音频和少量道具状态变化发生，不把整房替换成另一套传统恐怖资产。

#### 5.1.2 Boss 纸盒舞台视觉实现锁

网页原型先用 CSS/SVG 验证构图与信息层级；Godot 工程建立后按同一参数迁移，不重新发明视觉语言。

| 层 | 实现规格 |
| --- | --- |
| 镜头 | `Camera3D` 正交投影；Yaw `45°`，Pitch `35.264°`；固定朝向，不允许常态自由旋转 |
| 房间 | 每格为有厚度的纸盒托盘；顶面保持可读，侧面厚度约格宽 `12%～18%`；门洞贴合菱形边 |
| 比例 | 玩家视觉高度约单格 `1.4×`；Boss `2.5～3×`，允许视觉跨格但逻辑占格不变 |
| 灯光 | 玩家暖橙聚光、Boss 洋红侧逆光、信号锚暖橙点光；环境底色深墨 `#12141D` |
| 材质 | 纸板高粗糙度、黏土中高粗糙度；法线只表现纸纤维/指纹，不叠赛博描边 |
| 后期 | 暗角与 CRT 扫描线放在 `CanvasLayer` / Compositor；不得降低格线、威胁区和门向可读性 |
| HUD | `CanvasLayer` 顶部节目票根高 `64～72px`；右侧手牌栏保持 `300px` 等效宽度；战斗全程单屏 |
| 动效 | 镜头震动、强闪和近景只用于阶段切换/终结，单次约 `0.3～1s`；玩家回合常态保持稳定全局视野 |

### 5.2 音频

- 节目旁白、串台杂音、对讲机/电视机失真（多人尖叫尤其靠听）  
- 战斗反馈短促；Boss「播出」用广播感压迫  

### 5.3 文案语气

短、怪、像主持人念稿；嘲笑**节目组/失控布景**，避免纯羞辱玩家。

## 6. 多人愿景（招标可选包，非当前必做）

详细短稿：`cabin-slice/data/multiplayer-haunt-sketch.md`。

### 6.1 恐怖片流程

```text
大厅集结 → 分头探索 → 单人事件/战斗 → 出事/尖叫 → 合流
         → 预兆压满 → 半场奸徒揭晓 → 不对称后半
         → 整图 Boss 终局
```

- 大厅/脱战：**实时移动**  
- 房内战斗：可保留**回合制放置战**；中途加入从门口进场  
- 爽点：闲逛时听见尖叫、推门看见队友窘迫、选择救或不救  

### 6.2 半场奸徒 ≠ 狼人杀

| 要 | 不要 |
| --- | --- |
| 前半真合作 | 开局隐身份 |
| 半场规则换页 | 投票放逐 |
| 空间型伤害：假尖叫、锁门、搅局、推播出 | 抽象「刀人」夜勤 |

### 6.3 终局 Boss：整图 + BG3 战斗检测

- 每个房间**压缩为一格/节点**，格上套用对战规则（尺度改编）  
- Boss **感知范围**：内=交战；外=即时跑、搜、藏、破机关  
- Haunt 分工：**有人拖，有人飞毛腿破机关**  
- 地图必须同时提供：**拖怪点、跑线、藏匿点**  
- 范围过小/过大都会坏掉；**视野、遮挡、噪音**与半径一起调

## 8. 分期里程碑与招标包

报价请按包拆开；**默认只采买当前勾选包**。人月为「熟练独立游戏程序+关卡」量级粗估，含联调不含发行市场。

### 包 A — 单人网页「节目感一集」打磨（优先）

**目标**：从「跑团规则模拟」推到「短、怪、记得住的一集」。  

范围：压战斗占比；补 1～2 种短事件（如拼图）；旁白/播出包装；Boss 手感与中段曲线；内容小扩（牌/房）；增加 Lili「事实日志 → 本集回顾 → 记忆碎片」最小闭环；不换引擎，不做运行时生图。

**工期**：约 **1.5～3 人月**  
**验收**：陌生玩家 25～40 分钟打通或明确失败；能复述「放置走位」与「节目感」；回顾与战局一致且 Lili 口吻可辨；AI 不可用时仍能正常结算。

### 包 B — Godot 单机技术样片

**目标**：同规则迁引擎 + 微缩视觉样板房 + 单人整图 Boss 雏形（压缩格 + 脱战跑）。  

范围：核心战斗迁移；1 集教学节目；1～2 个景深展示房；终局地图原型；基础音画管线；角色档案、回顾空间和后台日常的数据骨架。

**工期**：约 **6～12 人月**  
**验收**：样片可录 3 分钟实机预告；脱战破机关分工在单人下可玩通。

### 包 C — 单机「一季」内容扩写

**目标**：多结局/多 Boss/牌怪池/叙事包装达小型商业独立作；在核心玩法稳定后加入自建 OC、微习惯与角色卡导入导出。

**工期**：约 **1.5～3 人年**（可在 B 后并行美术）  
**验收**：3 次以上重玩动机；一季内系统不再大改。

### 包 D — 多人合作 + 半场奸徒 + 整图终局联机

**目标**：致命公司式分头合流 + Haunt 奸徒 + BG3 脱战终局。  

**工期**：在 C 基础上再 **+1～2 人年**  
**验收**：4 人一局完整恐怖片流程；奸徒局空间博弈成立；不出现狼人杀投票主循环。

### 包 E — 旁支（可选）

金山打字式联机追逐等 PvP 小模式——**独立报价**，不阻塞 A/B。

## 9. 招标说明（给协作方）

### 9.1 甲方已有

- 可玩网页原型与规则数据  
- 美学与非目标清单  
- 设计短稿与本文  

### 9.2 乙方需提交（投标）

1. 理解复述：一句话 +「不是什么」  
2. 所选包：A/B/C/D/E 及报价、人周拆解  
3. 里程碑与风险（尤其：地图×Boss 范围、联机同步）  
4. 过往作品：空间战术 / 邪典或强风格表现 / 联机（若投 D）  
5. 沟通：能否接受「克制小玩法、半场奸徒≠狼人杀」为验收条款  

### 9.3 知识产权与协作

- 角色与 channel 品牌归项目方；外包交付源文件与授权范围合同另定  
- 小步提交；关键玩法先可玩再贴皮  
- 禁止擅自把主线改成派对或验人局（属重大违约级范围变更）  

### 9.4 成功标准（产品级）

玩家离开后记得住四件事中的至少三件：

1. 「我是在用陷阱和走位打架，不是站桩」  
2. 「这像一集坏掉的儿童节目」  
3. （若多人）「我们分头行动，后来有人翻脸 / 有人拖 Boss 有人跑机关」  
4. 「Lili / 我的 OC 记得刚才发生过什么，而且说话像同一个人」

## 10. 风险登记

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| 范围蔓延成派对/联机大坑 | 高 | 硬否决表 + 分包采购 |
| 终局 Boss 范围难调 | 高 | 地图与半径同迭代；先单人验证 |
| 网页规则迁 Godot 损耗 | 中 | 数据驱动；战斗系统单测 |
| 仅规则像跑团、无节目感 | 中 | 包 A 强制做包装与节奏 |
| 奸徒做成狼人杀 | 中 | 验收禁止投票主循环 |
| 内容池不足重玩空洞 | 中 | 包 C 专责内容，不提前开 D |
| AI 回顾编造事实或 OOC | 高 | 结构化日志、事实校验、人设校验、模板降级 |
| AI 成本/延迟阻塞一局 | 中 | 异步生成、限长、缓存；AI 服务不可用时照常结算 |
| OC 功能膨胀成独立陪伴 App | 高 | 只生成与节目经历相关内容；以本文硬否决表验收 |
| 角色与记忆隐私 | 高 | 最小采集、显式授权、可导出/删除；首期不接外部生活数据 |

## 12. 结论（给决策者）

channel 已具备 **可玩的规则心脏**；AI OC 将成为它的 **角色记忆与情感层**，而不是另一款并行产品。项目仍缺节目身体、关卡作者力、可信的局后回顾，以及愿景层的整图/多人。

**推荐采购顺序：A → B → C；D 单列评估。**  
用包 A 同时证明「邪典节目一集」和「一个记得这集的角色」成立，再为微缩 3D、自由 OC 与 Haunt 终局付钱。AI OC 的扩展不得先于核心肉鸽体验成立。

# 大地图 Boss 第一版

入口：标题 → 后台测试 → 大地图 Boss · 独立试玩 → 开始终局。正式一局到终局时使用已经搭建的大地图，不新建祭坛副本。

进入终局只叠加 Boss、四个信号锚和战斗提示。准备终局、进入战斗、行动刷新均保留原大地图节点、房间网格、家具与材质；仅从存档续玩时重新构建场景。扩建插槽在终局隐藏，房间资产不替换。

终局棋盘直接取已经探索完成的大地图占用格：大地图一格就是 Boss 战一格。1 格、3 格、5 格房间不再压成一个移动节点，房间内部相邻格可连续行走，跨房间只能通过两侧都存在的门洞。房间实例只负责保留房间名称、规格和美术归属；战斗位置、路径、攻击范围和机关位置全部使用真实大地图坐标。

后台试玩固定复用正式房间规格，包含玄关加17个房间实例，共18个房间；当前示例把地面层、二楼和地下室接成一个大地图，并展开为全部物理战斗格。正式一局则直接使用本局实际完成的房间和对应物理格。

三层的战斗坐标与显示坐标分离：大地图逻辑坐标仍保留楼梯、门洞和寻路关系；房间显示使用各自楼层的 `floor_origin` 折叠到同一塔心，并通过 `floor_height` 只改变高度。因此二楼、地面层和地下室是同一栋“蛋糕塔”的上下三层，不会因为逻辑坐标位于不同地图通道而在画面中散开。房间资产、1/3/5格轮廓和家具不替换，只改变楼层组合时的放置基准。正式布景按楼层分别建立 `KenneyFormalComposer`、`KenneyFormalComposer_Floor_1`、`KenneyFormalComposer_Floor_-1`，每个合成器拥有独立的 `GeneratedMap`、占用表和门连接键，避免不同楼层在生成器内部互相判定为重叠。

## 操作

- 点击可达的大地图格子会沿路径逐格行走，也可用原战斗方向按钮或 WASD/方向键一步一步移动。三格/五格房间保留每一格；房间内部可连续走格，跨房间按实际门洞判断，不按房间编号跳转。
- 整场终局使用统一回合制，没有脱战、藏匿或接敌切换。移动与出牌共享本回合 AP；点击“回合结束”后才执行一次 Boss 行动并推进播出。普通追击会在敌方回合按玩家当前位置重新寻路；冲撞和扫场保留已预告区域。
- 沿用原战斗手牌、血条、行动力、抽弃牌区和回合按钮。点放置牌，再点目标房间，或直接拖牌到房间；自身效果直接生效。再次点牌、右键或 Esc 取消选牌。结束回合执行已预告动作。
- 四个信号锚分布在可达的大地图战斗格，优先每个房间实例一个；走到锚所在格后操作，每次2AP，共两次。关闭减播出2、减Boss韧性上限1。
- 局部边线提示：红为已预告攻击，金为摄影取景，青为相连房间；鼠标悬停房间亮金色边线。提示不覆盖或染色原有地板。取景房额外增加播出。
- Boss 战左侧增加楼层滑轨：二楼、地面层、地下室、三层总览和“回到玩家”。切换只改变可见房间与镜头取景，不消耗 AP、不推进回合、不改变玩家或 Boss 的逻辑位置；当前玩家所在层用圆点标记。三层总览用于确认楼梯、锚点和 Boss 的相对关系，回到玩家用于快速恢复战斗操作视角。
- 玩家站在楼梯入口格时，右侧显示“使用楼梯”按钮和目标楼层、AP 消耗；点击后沿现有战斗图跨到对应出口格。键盘方向键和地图点击也沿用同一条路径规则。跨层会增加1 AP，成功后自动切换到目标楼层并让镜头跟随玩家；行动力不足时只显示原因，不会移动。
- 击败Boss或关闭全部锚获胜；生命耗尽或播出满18失败。点击“查看结局”结算。
- 返回标题保留正式终局进度；再次续玩通过初始条件和操作日志恢复位置、牌、HP/AP、锚、回合和播出进度。试玩不写入或删除正式存档。

## 当前范围与验证

当前为真实大地图物理格版；点击远处可达格后逐格移动，也支持 WASD/方向键。单人终局不启用脱战、藏匿或接敌切换；房间内的每个物理格就是 Boss 战中的一个格子。三层原型通过显式楼梯边连接，跨层移动额外消耗1 AP；多人模式若需要独立参战范围，再单独设计。

WASD 与战斗方向按钮相同，每次执行一个大地图物理格移动；点击远处格子则复用同一套单格移动，逐步走完合法路径。鼠标拖地图旋转、中键平移、滚轮缩放和镜头复位继续控制原大地图相机。

目前不同Boss保留本局选择的名称和生命，暂时共用同一大地图回合战斗程序；Boss普通回合为4AP，最多追击两格后攻击，并按事件逐格移动、攻击演出。七种专属机制尚未逐个迁移。

`overworld_boss_regression.gd` 验证实际地图保留、1/3/5规格的物理格展开、门洞连通、等待不自动推进、主动结束回合、真实跨格拆锚、真实基础牌击杀、JSON操作日志恢复，以及两类失败。示例地图 seed1337 的拆锚与击杀路线均可成功；这些不是难度平衡或人工操作验收结论。

旧的 `boss_progression_regression.gd` 保留旧房内规则数据的回归覆盖，不代表正式终局仍在副本房间里。

`overworld_boss_scene_ui_regression.gd` 检查准备/入场/行动后原房间节点、几何、材质和布局不变，Boss 实例不随界面刷新重建，并通过真实 HUD 输入验证逐格点击路径、方向键、拖牌伤害、选牌取消、镜头操作与 2AP 拆锚。

该回归同时验证三层房间在显示层归一到同一塔心、进入 Boss 战默认显示玩家楼层、滑轨切层不改变回合/AP、二楼按楼层高度正确拾取战斗格、楼梯入口往返和 HUD 楼梯按钮，以及二楼视图只显示二楼正式布景、总览恢复全部楼层。

# 完整一局验收清单

后续修改的最终目标：按《织梦频道_channel_dream_策划案与招标书》第 3 节，使玩家能从主页开始、正常完成一局并返回主页；优先修复打断这条流程的问题。

## 已建立的自动化验收

`godot/tests/complete_run_flow_regression.gd` 使用隔离存档，覆盖：

- 预兆选择后开始探索，按实际门连接移动，扩建后未知房不泄露名称。
- 每间房只完成一次；战斗奖励、事件成功/失败继续推进；达到当前 12 房计数进入祭坛。
- 中途返回主页续玩；随机状态精确恢复；没有随机状态字段的旧档仍可读取。
- 速度成长增加下一战固定行动力，开局仍是基础 5 AP。
- Boss 胜利/失败到结局，普通战败返回主页，完成的一局清除续玩存档。
- 地编按 1/3/5 格筛选；客厅 living 是 1 格，会客室 parlor 是 3 格。
- 事件/静室可无副本；独立副本导出被正式战斗读取且不覆盖大地图布局。

自动化通过状态流不代表平衡或人工通关已经验收：测试模拟战斗结果，Boss 仪式动作另由 boss_progression_regression 验证。

本轮验证：完整流程、成长存档、Boss、正式扩建、双编辑层、副本导出、正式覆盖导出、多格房、测试隔离、回合时序、地编烟雾测试共 11 组断言通过；地编烟雾测试退出时仍有 Dummy renderer RID 资源未释放警告，退出码为 0，此项未作为已修复问题。已检查 1920×1080 的地编和手编副本画面。

## 后续修改顺序与人工验收

1. 正常操作通关：不改血量、不强制胜利，分别走战斗较多、事件较多路线；记录每房耗时、损血、奖励选择和无法继续的步骤。失败后能重新开始。
2. 战斗可读性：在 1/3/5 格副本逐个检查角色、危险格、家具和门的遮挡；验证所有需要到达的目标和 Boss 锚点可达。副本家具/墙体是表现层，不能暗中变成逻辑碰撞；战斗阻挡与高差仍从 arena 定义。
3. 一局成长：每项奖励有实际收益；牌库在战斗之间正确保留；查验策划中的中点遗物保底与战斗/静室/事件约 40/35/25 配比，不能仅依据单元测试宣称已实现。
4. 续玩边界：当前战斗/事件续玩按已有房间检查点重开，不承诺恢复战斗中某一回合。后续若要求精确续战，需要存储战斗状态并单独验收。
5. 结局与重玩：通关、仪式失败、普通战死的反馈清晰；返回主页后新一局不继承旧场景状态。AI 回顾等扩展不得阻塞核心单机流程。

策划写“约 10 房”，当前程序用 12 房（含玄关）。本轮保留现有计数，后续根据完整试玩结果统一节奏，避免同时变更规则和修复流程。

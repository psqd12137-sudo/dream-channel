## 1. 体验定位

### 本轮实施与验收记录（2026-09-09）

- 已实现：工作台与边框、低对比孟菲斯地板、模块局部印花坐标、涂漆/黏土/毛毡粗糙度分层、探索反射与接触暗部；正式和分格表现均绕共同中心落位，落稳后复用合法入场。

- 定向回归覆盖：重复确认、正常/零时长、落位中退出与继续、未知中间房阻断、已访问中间房通行、分格整体动作、非居中地图底板覆盖、印花附着和材质分层。
- 相关回归通过：动态演出、正式五格拼装、楼层往返与存档、信号锚、局内保存、完整流程、占格、候选、镜头跟随与旋转、表现动画、表现设置和 UI 命中。完整流程模拟战斗结果，不表示进行了平衡测试。

### 1.1 一句话体验

玩家像坐在儿童节目工作台前，从收纳盒取出一块孟菲斯风格的房间玩具，对齐接口，按下卡合；屋内角色看着新模块落位，随后从连接处跳过去，让刚拼好的布景开始活动。

玩家承担“摆放布景的人”，角色承担“在布景中生活与冒险的演员”。两种尺度通过镜头、声音和动作衔接，不新增双角色控制或手部模拟。

### 1.2 三个核心感受

1. **拿得起来：** 房间具有底座、侧边、厚度和接口，墙、地板、家具随整块模块共同运动。
2. **拼得进去：** 合法连接有清楚的对位、吸附、下压和卡合反馈，操作结果明确。
3. **拼好会活：** 角色在落稳后进入，房间随后揭示和激活，形成“我刚造出的空间被角色使用”的反馈。

### 1.3 对参考的使用范围

参考来源：[小红书笔记](https://xhslink.cn/o/7vRqD3OzRQl)。本轮已经通过浏览器看到一帧实际赛车演示画面：蓝黄主体、灰色路面、宽高光、较暗背景和较强透视。

借鉴表面光泽、接地阴影、物体体积和主体明暗分离；不复制赛车内容、低机位、HUD、配色分配或未知的技术实现。对参考的判断仅基于已看到的画面，不声称审查了完整视频或源工程。

孟菲斯风格与玩具屋设定来自用户本轮要求；用项目自有图案、资产和构图建立最终方案。

## 3. 孟菲斯美术规范

### 3.1 形状语言

使用圆柱、圆盘、半圆拱、阶梯、楔形、圆角矩形、斜切板和不对称组合。主形体必须先能辨认房型，再加入装饰。

- 底座：圆角厚托盘，外缘有轻微倒角；局部露出层压纸板或木件截面。
- 墙体：可拆插板结构，墙顶、门洞、侧边具有实体厚度；保留可见装配缝。
- 家具：床、桌、椅、柜仍具有明确功能，允许粗短圆柱腿、偏心圆桌和不对称色块。
- 接口：连接处使用插舌、凹槽或短桥板的视觉语言，与真实门边一致。
- 装饰：锯齿、波浪、圆点、条纹、棋盘格和散点纹理只选择少量组合，不全部叠在同一表面。
- 每个房间保留至少一处节目证据和一处可激活的荒诞破口，沿用主策划要求。

### 3.2 配色起点

| 色彩 | 起始值 | 主要用途 |
| --- | --- | --- |
| 奶油纸白 | `#F7E8C5` | 内衬、纸板、标签和视觉留白 |
| 深墨 | `#12141D` | 外部舞台、文字和小面积图案 |
| 青绿 | `#23AA9B` | 家具、模块侧边和辅助大色块 |
| 金黄 | `#F2A51E` | 把手、节目道具和少量强调 |
| 洋红 | `#D63B72` | 重点装饰与失控状态的局部变化 |
| 钴蓝 | `#3156C8` | 主墙、柜体和沉稳对比面 |
| 珊瑚 | `#D9574F` | 房间局部暖色点缀 |

青绿、金黄、洋红、珊瑚和纸白与当前房屋渲染器已有色彩衔接。建议单个房间以约 60% 安静基底、30% 主色、10% 强调作为构图起点，比例按可见画面面积判断，不要求每件资产机械套用。

规则信息使用独立标记层。合法、非法、威胁和选中状态同时有图标、线型或文字，不能只依赖颜色；原有战斗地形色与威胁色仍按既有语义呈现。

### 3.3 图案密度与坐标

- 一间房间最多选两种主纹样、一处小型标签装饰；通行区域保持低频、低对比。
- 模块侧边可以使用较强棋盘格、斜纹或波浪；主活动地板采用稀疏大图形。
- 家具上已有强纹样时，背墙降低复杂度。
- 图案尺度以房间局部单位定义，不随房间缩略图尺寸变化而重新随机。
- 同一实例内图案连续；不同模块之间允许接缝和相位变化，强调拼装身份。
- 移动和旋转时图案必须附着在模块上。当前 `memphis_floor.gdshader` 使用世界位置，实施时改为模块局部坐标或显式模块变换后的坐标，保留跨子网格连续性。
- 纹样变化使用独立的确定性视觉种子，不消耗玩法随机数序列。

### 3.4 材料与高光

| 材料 | 建议粗糙度起点 | 表现原则 |
| --- | --- | --- |
| 纸板 / 印刷内衬 | 0.82～0.98 | 高粗糙度，轻微纸纤维，不做湿亮反射 |
| 涂漆木件 | 0.38～0.60 | 宽而柔和的高光，边缘有厚度 |
| 塑料把手 / 卡扣 | 0.22～0.40 | 高光更集中，作为局部材质对比 |
| 黏土 | 0.65～0.90 | 细微手作起伏，避免像镜面树脂 |
| 毛毡 / 布料 | 0.90～1.00 | 柔和暗部与低频纤维，远景不产生噪点 |
| 小面积金属件 | 0.25～0.50 | 独立金属材质，只占少量面积 |

非金属的 metallic 起点为 0。参考的光泽主要迁移到涂漆件、塑料件和局部地板，不把纸板、毛毡和角色统一改成亮塑料。

现有墙 Shader 的粗糙度固定为 0.98，地板为 0.92。计划增加材质类别参数，默认保留原值，按房间材质实例选择新值；禁止批量覆写第三方源资产的共享材质。

### 3.5 模块尺寸与结构

以逻辑格宽为 C 表达比例，不硬编码新的世界尺度。现有 `HOUSE_CELL = 3.4` 与 `VISUAL_CELL_SCALE = 1.20` 继续作为既有坐标换算的一部分。

- 底座厚度先取 C 的 12%～18%，与主策划既有纸盒托盘范围衔接。
- 倒角半径先取 C 的 1%～2%；在最终游玩镜头里可读即可。
- 装配缝先取 C 的 0.5%～1%，是视觉间隙，不新增逻辑断路。
- 门洞、楼梯和角色落点的净空由角色可见包围体与连接位置检查，禁止仅按好看决定。
- 3 格与 5 格模块是一个整体外壳，不能在动画中出现多个小格各自翻转的碎裂感。
- 前墙和盒沿服从现有遮挡剖切原则；不能为了盒体完整而遮住玩家、门和可交互格。

## 4. 工作台、收纳托盘与模块展示

工作台是低干扰的尺度参照：可见盒沿、收纳槽、编号贴纸、少量节目制作痕迹。桌面纹样低对比，房间与角色是主要视觉焦点。

首版使用局部盒沿与可延伸底板，不制作一个固定尺寸且会限制地图扩建的大外盒。不同楼层可表现为不同层的抽屉式布景，但楼层切换仍来自既有楼梯规则。

候选区域保留现有票根信息、布局和操作，可用槽位边框、材质和阴影表达收纳盒感。只有现有预览不足以识别模块时，才补充缩略预览、占格轮廓与门向，不强制替换新面板。候选数量跟随规则输出，不增加抽取数。

未知内容沿用现有隐藏与揭示方式：可展示外壳、占格、门位和规则已公开的标签；内部事件、敌人、奖励、隐藏道具不进入缩略图、图标、工具提示或辅助文本。封套图案可选，独立盒盖和抽盖动画不是首版必需项。

首版优先采用低面数外壳预览与缓存缩略图。只有当前选中模块需要实时展示，避免为每个候选运行一个高质量实时渲染视口。

## 5. 一次拼装的完整流程

### 5.1 正常流程

| 步骤 | 玩家动作 | 画面与声音 | 逻辑边界 |
| --- | --- | --- | --- |
| 进入拼装 | 点击现有合法扩建位置 | 沿用现有候选面板和预览，按需增加玩具盒材质 | 复用 `begin_build` 与 frontiers |
| 挑选模块 | 点击候选 | 模块抬起，票根标签与门向联动 | 复用 `select_offer`，不提前揭示 |
| 旋转对位 | 使用现有旋转控件 | 整块旋转，对位轮廓同步变化 | 复用 `rotate_offer` 与四向旋转 |
| 预览可行性 | 查看接口状态 | 合法显示插槽与卡合轮廓；非法显示阻挡位置及原因 | `room_rules.can_place` 为唯一合法性依据 |
| 确认 | 沿用确认按钮，提示是否自动进入 | 模块从悬浮位置降下 | 沿用放置验证，只提交一次建造 |
| 落稳 | 无需额外操作 | 底座短促下压、回弹，“咔哒”声 | 动画不再修改占格和额度 |
| 角色入场 | 可达时自动衔接，否则保留主动选择进入 | 复用原有路径与小跳，强化跨缝动作 | 只沿合法路径调用既有进入流程 |
| 内容揭示 | 沿用原有进入后的揭示 | 保留现有翻面并调整材质，抽盖可选 | 首次进入按既有 reveal / visited 时机提交 |
| 房间就绪 | 玩家继续原有操作 | 灯光稳定，小道具苏醒，恢复 HUD | 进入 `room_ready`，不自动结算事件或强制出牌 |

可自动衔接时在现有按钮旁提示将进入，只有文案有歧义时才改按钮名。建造失败沿用原有合法性反馈；自动进入不可达则提示“已拼好，请先到入口”，不拒绝原本合法的建造。

### 5.2 可达路径与跳跃边界

- 相邻且门连通：角色在旧模块入口附近准备，跨过连接缝，到新模块安全落点。
- 非相邻但能经已访问房间到达：落位后先沿既有合法路径移动，到最后连接处再做重点跳跃。不能一跳跨完整地图。
- 途中必须经过另一个未访问房间：不自动穿越，仍允许原本合法的放置；落位后回到既有探索流程，由玩家自行到达入口再进入。
- 跨楼层：使用既有楼梯连接；镜头切换楼层，角色在目的层做短入场跳跃，不从屋顶穿过上层地板。
- 落点由实际入口、占格与可用空间确定；人物家具互动槽不是天然安全落点，需要避开家具包围体。
- 重访已建房间保留既有导航；不重复拆封、奖励或首次入场演出。
- 已建模块首版不可拆除、搬走或重新分配家具；这些会扩展规则与存档范围，不包含在此计划。

### 5.3 动作节奏起点

| 动作 | 时长起点 | 约束 |
| --- | --- | --- |
| 候选抬起 | 0.12～0.18 秒 | 输入立即生效，不等待动画才能继续选择 |
| 旋转对位 | 0.16～0.22 秒 | 连续旋转以最终目标为准，取消旧 Tween |
| 落位 | 0.28～0.40 秒 | 首版取消整块约 82° 大翻转，改为小倾角抓放感 |
| 下压回弹 | 0.10～0.16 秒 | 只动外观层，最终缩放恢复为 1 |
| 角色蓄力 | 0.08～0.12 秒 | 角色先面向真实入口 |
| 跨缝跳跃 | 0.30～0.45 秒 | 弧线经过连接净空，阴影留在落脚平面 |
| 落地 | 0.08～0.12 秒 | 轻压缩与回弹，不变更逻辑高度 |
| 拆封激活 | 0.18～0.30 秒 | 可与落地后半段重叠，不提前暴露内容 |

相邻新模块从确认到恢复控制目标约 1.1～1.6 秒，不含玩家选择时间与远距离行走。可开启快速表现，将镜头与弹跳显著压缩；动画时长为 0 时仍必须执行相同的逻辑终态。

## 6. 灯光、镜头与后期

### 6.1 灯光方案

以柔和的节目工作台主光照亮模块，弱冷色补光保留暗部细节，局部边缘亮度分离盒沿。桌面背景比可玩区域安静，但不将整个房间压成黑色。

重点是三种信号：倒角上的窄亮边、涂漆面上的宽高光、家具脚下的接触暗部。现有固定颜色环境光可作基线，后续增加经验证的环境反射来源；动态拼装场景优先共享反射环境或有限的 ReflectionProbe，不为每间房实时更新探针。

SSAO 作为可选质量项，用来增强墙角和家具接触；先解决真实阴影、模型厚度和法线，再调强度。Forward+ 专有效果只在对应质量档启用，不将其作为所有渲染路径的强制依赖。

### 6.2 镜头方案

- 拼装镜头：同时看清来源模块、目标接口和角色所在位置，保留必要 HUD 安全区。
- 入场镜头：平滑跟随入口与角色，不采用赛车式贴地追逐镜头。
- 就绪镜头：回到当前房间的可读构图，保留下一步操作目标。
- 既有战斗与 Boss 全局镜头约束保持有效，拼装镜头不能泄漏到战斗阶段。
- 正交为首版默认；弱透视只作为样板比较项，必须通过屏幕拾取、门向、楼层与 HUD 回归后才能决定是否采用。
- 用户主动平移或缩放时处理明确：拼装确认后仅在短暂过场内接管；结束时依据既有镜头规则恢复，不能留在半途状态。

### 6.3 后期方案

保持 Filmic 作为初始对照；先关闭或减弱移轴模糊，验清材质与图案，再轻量加入焦点效果。活动房间、入口、角色和操作提示必须清晰；UI 不受世界后期影响。

泛光只用于少量灯泡和发光道具，常态不做全屏柔焦。图案需要抗锯齿与纹理过滤测试，尤其是倾斜棋盘格、细波浪和移动中的高对比边缘。

## 7. 音频与可访问性

优先复用已有声音，补足卡合与落地反馈。模块取出、转动定位、对位、轻碰、卡合、落地和揭示是可选声音类别；没有新盒盖动画就不制作拆盖声。纸板偏干、木件偏厚、塑料扣偏脆；卡合声和视觉接触帧一致。

悬停提示与对位声音限频，连续移动不重复轰炸。角色落地声按落点材质选择；外观随机音色使用独立视觉 / 音频随机源。

保留点击完成全流程，不强制拖拽精细操作。快速 / 减少动态模式关闭镜头晃动和大幅缩放，缩短跳跃与回弹；非色彩提示说明合法性。拼装过场允许快速完成，结果与正常播放一致。

### 9.2 模块节点契约

```text
ToyModuleRoot                    # 稳定的 instance_id 和逻辑锚点映射
  MotionRoot                     # 整模块拿起、旋转、落位
    BaseMesh                     # 完整底座
    RoomContentRoot              # 墙、家具、节目装置
    CoverRoot                    # 未揭示内容的封套 / 盒盖

    EntryAnchors                 # 根据实际连接生成的入口参考点
  SelectionOverlay               # 规则提示，与纹样分开
```

角色由独立 ActorMotionRoot 驱动，内部保留 CharacterPresenter。不要把角色挂在正在落位或压缩的模块下面；落地后也保持稳定的角色所有权，以免房间刷新删除演员。

### 9.3 接口草案

以下为规划接口，不是现有已实现 API。数据源统一来自控制器已经验证的实例快照。

```gdscript
# ToyModulePresenter
func configure(instance_id: String, visual_snapshot: Dictionary,
        style: ToyStyleProfile) -> void

        destination_cell: Vector2i, entry_path: Array[Vector2i]) -> void

        progress: float, height: float) -> Vector3

```

`public_offers` 是脱敏后的显示数据：仅含现有公开名称或未知标签、轮廓、门向、旋转和合法性说明。禁止直接绑定含隐藏内容的完整 room Dictionary。

`visual_snapshot` 只供受控表现器使用；在 revealed=false 时禁止创建可见的秘密内容和由秘密决定的封套差异。instance_id、footprint、floor、连接与入口由规则快照取得；风格参数不反写规则。

### 9.4 坐标与动画所有权

统一沿用 house_root 的视觉缩放链。世界点、房间局部点与楼层原点通过已有变换换算；不能在跳跃距离、底座尺寸或门坐标中再次手动乘 `VISUAL_CELL_SCALE`。

同一时刻一个节点只能由一个组件驱动 transform。选择动画由模块表现器负责；正式拼装由 AssemblyDirector 调度；角色内部姿势由 CharacterPresenter 负责；外层位移由 ToyJumpMotion 调度。

活动动画记录 generation/token。返回主页、开始新局、替换预览、快速完成时递增 token 并杀死旧 Tween；旧回调检查 token 后退出。不要在旧场景回调中写新局状态。

## 10. 状态、存档与异常

### 10.1 表现状态

```text
空闲 → 挑选 / 对位 → 再验证 → 已提交建造 → 落位
     → 路径接近 → 跨缝跳跃 → 首次揭示 → 房间就绪
```

正式 `phase` 继续由现有控制器管理，不把以上状态全部加入玩法 phase。Director 内部区分动画子阶段，`animation_busy` 阻止重复建造和重复进入，但允许暂停与快速完成。

### 10.2 提交策略

1. 确认时沿用放置合法性检查；可达性只决定是否自动衔接进入，不改变能否建造。
2. 复用现有建造调用，只提交一次实例、候选消耗和 pending_room_pos。
3. 按现有时机保存“房间已建、角色尚未进入”的合法快照，再播放表现。
4. 落位后可达时沿既有路径进入，不可达则保留原探索状态等待玩家操作；入场 / 揭示结束仍通过 `_finish_enter_room` 提交访问状态并保存。
5. 首版不保存半空坐标、Tween 进度、镜头位置、托盘悬浮状态或粒子。

中断恢复到最后一次成功保存的合法状态：若房间已建但尚未进入，恢复为已落稳的未知模块，角色保留在最近保存位置，显示“新模块已拼好，点击进入”。不强制读档后自动触发演出或事件。

内存中建造成功但写盘失败时，不重试建造、不重复扣除。提示本次进度未能保存；后续保存仍通过现有存档机制，不能宣称已经具备事务性或原子文件替换。原子存档升级如确有需要另列专项。

### 10.3 异常矩阵

| 情况 | 预期行为 |
| --- | --- |
| 没有候选 | 显示空托盘与原因，保留返回探索，不访问下标 0 |
| 连续切换 / 旋转 | 旧动画被取消，最终预览与 selected_offer / offer_rotation 一致 |
| 非法放置 | 保留预览并显示原因，账本、候选、角色位置不变 |
| 连续点击确认 | 只生成一个实例，只进入一次，只追加一次首次访问日志 |
| 确认前取消 | 模块归位，取消楼梯预建状态，保留原有取消语义 |
| 提交后按返回 | 完成或中止表现到合法快照，不把已建实例偷偷回滚 |
| 动画时间为 0 | 直接到正确终态，包含自动入场与揭示，不漏发完成通知 |
| 中途退出 / 重开 | 清理旧 token、Tween、信号和相机接管，旧回调不可写入新局 |
| 入口有视觉遮挡 | 调整同一合法入口的表现路径或墙体剖切，不修改寻路与碰撞规则 |
| 找不到模块节点 / 角色模型 | 使用既有占位 / 精灵表现并快速完成，不能永久锁住输入 |
| 楼层切换 | 模块、入口、角色与相机使用同一目的层坐标，隐藏非活动层不误隐藏角色 |
| 读取旧存档 | 按 instance_id 重建新外观，缺失风格字段用默认值，不重新抽房 |

### P4 / 任务 5：卡合、跳入与揭示编排

**文件：** 拟新增 `toy_assembly_director.gd`、`toy_jump_motion.gd`、`godot/tests/toy_assembly_regression.gd`；修改 `channel_3d.gd` 的建造 / 入场薄接入。

**输入：** 已验证并提交的 instance_id、destination_cell、合法 entry_path 和模块表现器。
**输出：** 一次完整拼装到 room_ready 的流程及 `assembly_finished`。

- [ ] 先测落位完成后才开始角色入场，首次访问结束只发生一次。
- [ ] 为弧线采样测试起点、终点与中点高度，再检查角色包围体沿入口路径无明显穿墙。
- [ ] 以 generation/token 管理串联，接入快速完成和动画时间为 0 的同终态路径。
- [ ] 使用现有 enter_room / house_path_to 验证已访问路径，禁止跨未访问房间抄近路。
- [ ] 保留现有翻面揭示和 room_ready 边界，不自动结算事件；抽盖只有明确视觉收益时才列为增强。
- [ ] 检查 CharacterPresenter 动作重置不会覆盖 ActorMotionRoot 轨迹。

**基础弧线契约测试示例（仅计划代码）：**

```gdscript
var a := Vector3.ZERO
var b := Vector3(2.0, 0.0, 0.0)
assert(ToyJumpMotion.sample_arc(a, b, 0.0, 0.5).is_equal_approx(a))
assert(ToyJumpMotion.sample_arc(a, b, 1.0, 0.5).is_equal_approx(b))
assert(ToyJumpMotion.sample_arc(a, b, 0.5, 0.5).y > 0.0)
```

采用 `lerp(start, end, t) + UP * 4h*t*(1-t)` 作为直线跨缝段起点；到入口前的路径单独处理。曲线不等于可达性与净空验证，不能用此三条断言替代正式入场测试。

**验收：** 正常、快速、零时长三种播放方式得到相同房间实例、角色位置、revealed、visited、phase 与事件日志。

### 13.3 核心通过标准

- **风格：** 不看说明也能辨认出几何撞色、玩具制造结构和盒中微缩尺度。
- **材质：** 纸板、涂漆件与毛毡看起来属于不同材料；没有全场湿亮或同样灰哑的问题。
- **拼装：** 模块整体拿起、门位对准、落稳卡合，动作顺序清楚。
- **角色：** 等房间落稳后才跳入，真实经过连接，落点无明显穿模；事件仍由原流程处理。
- **规则信息：** 未知内容不提前暴露，门、楼梯、威胁区、信号锚和选中格能辨认。
- **可靠性：** 重复点击、中断、快进、读档与零时长结果一致，无重复建造或访问。
- **性能：** 记录指定测试机上的结果。首轮目标为 1080p 完整地图稳定接近 60 FPS，95 分位帧时间目标不高于 20 ms；不足时先降低效果，不减少规则内容。该目标是计划值，不是当前性能承诺。
- **稳定性：** 连续 50 次样板拼装 / 重置后，活跃 Tween、模块节点和音频播放器没有持续增长。

### 14.2 风险与处理

| 风险 | 处理 |
| --- | --- |
| 孟菲斯纹样抢走战斗注意力 | 强纹样集中于侧边与墙面，活动平面安静，规则覆盖层独立 |

| 实时缩略图 / 反射过重 | 缓存缩略图、仅选中项实时、共享反射环境、按质量档降级 |
| 推广到全图后颜色失控 | 使用有限风格预设，并以 12 房拼合视图进行二次验收 |

## 15. 本轮交付与后续边界

本轮交付只有这份计划书；没有创建计划中列出的脚本、场景、材质、模型、音频或测试，没有运行 Godot，也没有提交或发布。

未来最小可验收成果是：**一张孟菲斯玩具工作台、三种合法占格的房间模块，以及“挑选 → 对位 → 卡合 → 角色跳入 → 未知房间揭示”的完整片段。**

首版不包含自由拖拽编辑全部家具、拆除已建模块、玩具收集经济、赛车玩法、联机同步或全量角色重制。它首先统一现有空间构筑的视觉和操作表达。

执行前需要核定的制作选项已给出默认值：外层盒体采用可延伸舞台；角色材质保留黏土 / 毛毡身份；输入保留点击；镜头保留正交；首批复用既有三种占格房间。只有用户另行改变这些选项时，才相应调整范围和排期。

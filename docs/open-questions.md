## 0.1 现实玩具、电视梦境与三阶段循环（2026-09-10）

已确认方向已写入主策划第 0.1 节，展开见 [专题总结](./design/2026-09-10-现实玩具与电视梦境.md)：现实拼装投射为电视中的梦境节目；游玩使梦松动；监管力量试图提前终结梦；结尾角色恢复为静止玩具；精彩演出通过电视订购兑现为现实玩具内容。

尚未确定：梦境松动的推进与显示规则；三阶段触发及 Boss 数量；提前醒来与完成梦的胜负区别；自制房入池和结构继承；精彩演出判定、失败解锁、费用与收货时机；现实层的奇幻边界；AI 记忆与后台日常如何兼容静止玩具。暂不把“12 房、两次彩排、一次播出”或每层 12 房作为确认规格，也不引入真实货币交易。

本方向更新局外工房的世界观与获取包装，但下文 2026-08-26 的低权重投池、时间线零件和家具机制仍保留未决状态。现有客户端规则不因本文自动变更。

## 0.2 三阶段多人演出：已确认结构与待验证规则（2026-09-10 后续更新）

现行方向见 [主策划第 6 节](./design/织梦频道_channel_dream_策划案与招标书.md#6-三阶段多人演出与终幕破坏秀)，更新此前关于三阶段结构、房间投注和出演资格的未决口径：

- 恰好三个阶段，合作逐步加入对抗与被迫误伤；第三阶段末尾的 Boss 战就是颁奖仪式与最终破坏秀。核心是演出和欢乐，不做搜打撤。
- 自建房作为第一阶段投入，可弃权；候选是该玩家走过的地块。全员弃权仍从已走过的房间随机选取；唯一投注者不能锁定结果。区域受伤越重，抽选权重倾向越高。
- 房间局内一次性、不重复；早获得自制房更容易获得自己配置的牌组。信物也加入演出评分，稀有度和难度越高加分越多。
- 出演资格按马里奥派对式累计与颁奖结算方向设计，替代简单“价高者得”；三个阶段各取玩家信物素材生成最终剧本，保留 PvE 终幕。

待验证：

1. 阶段房数、触发条件、小 Boss 数量、颁奖与变身在终幕内的顺序。
2. 万能房随时放置或入卡堆随机抽取；房间不重复按模板／实例如何定义，多人同房如何处理。
3. 候选池的跨玩家合并、区域伤害统计、权重与上限；全弃权是否沿用加权抽选，如何避免单一候选池导致必选。
4. 稀有度和难度的认定、信物评分公式、自建房是否需成本约束；演出奖项、平分、出演拒绝和 PvE 处理。
5. 三阶段素材组合规则、阶段小 Boss 的生成与触发，以及弃权时的替代素材。
6. Boss 前不直接死亡的倒地和恢复规则，阶段小 Boss 是否可致死，最终胜负与破坏秀参与方式。
7. 多人回合、同时行动、联机实现；单机设计边界已在下节明确，具体实现尚未完成。

上述结构未实现；暂不把助手举例的具体奖项、反派能力、权重算法视为已确认规则。

## 0.3 单人竞拍仅决定剧本（2026-09-10 已确认）

主策划第 3.0 节锁定单人边界：不需要两名玩具嘉宾或虚拟参赛者，无竞价对手、排名竞争和反派选角。三个阶段分别投入信物或弃权，从玩家自己走过的地块抽取素材；第三阶段末尾将三份素材组成颁奖式 PvE 破坏秀。唯一投注者不锁定结果，弃权仍正常抽选。叙事上扮演反派不构成奸徒机制。

仍待验证：单人评分的具体奖励用途、信物投入与概率的映射、候选过少时如何避免必选、区域受伤权重、阶段长度、三份素材组合和 PvE 胜负条件。评分不默认等于抽选权重；自制房随时放置／随机入堆仍未确定。本节不改变多人按演出成绩分配出演资格的方向。

## 1. 成长主轴：牌库构筑 vs 能力值系统 → 片场工房

**现状**：一集成长仍是牌库（战后选牌 + 遗物跳变 + 静室小数值）。对抗靠放置 × 走位，明确不做山屋惊魂式力量拼点。大地图格子已是房间实例占位（1 / 3 / 5 格共用 `instance_id`）；进战为更细棋盘，按同一 footprint 裁外形。

**倾向口径（2026-08-26，未进主策划、未实现）**：局外成长改为片场工房；角色不走英雄 / 职业菜单。全文见 [片场工房与角色类型](./design/2026-08-26-workshop-and-kits.md)。

- 原 2026-08-26 方案为“一整局只有一个祭坛 Boss、时间线是剧情奖励轨”；该旧口径不限制主策划第 6 节的新三阶段多人方向，小 Boss 数量与触发仍待定。
- 局外：时间线发零件 → 地编搭一间装备房 → 开局低权重进入揭格 / 票根池。没搭房也能开一集。
- 抽到自制房：探索更好打、奖励加一档；Boss 对应到该实例时用家具 combo。不加攻击数字。
- 家具优势：站上格子花行动力，用六类场景动词（挡住 / 站上去 / 推开推倒 / 撒一层 / 弄暗弄亮 / 藏进去），复用现有挡格、高差、盐圈、视线。不进牌库，不为每件家具写新卡文。
- 身份：引擎抄尖塔 **2**，卡面抄喵喵定位（在哪 / 怎么挪 / 落点）。移动即防御。少量真格挡，大量道具 / 动作 / 预备。先四套：奇巧、铁甲、故障、亡灵。储君后置。观密作废。
- 明确不做：区域数值光环、局外日历 / 升级金、没搭房不准开局、互动牌进本局牌库、英雄名册、开局职业菜单、把牌身份写成属性轴、开局掷攻击力、先拆专属奖励池、用 1 代观密当第四套、按尖塔每人四五张防御写开局、新卡写成纯数字打击、先做朝向背刺。

**旧候选（搁置）**：A. 面板加点；B. 少量主动技能栏；C. 对抗掷骰（战斗拼点）。均让位于空间构筑。开局掷生命 / 速度 / 手牌不是 C，不视为已否决。

**暂定**：切片继续现行奇巧开局。铁甲 / 故障 / 亡灵开局列表与掷套未写入 `cards.json`。储君未设计开局。工房与家具动词同样先不改正式战斗规则。

## 2. 战斗视野与意图预警

**问题**：无视线时敌人仍在真格显示 `?`，但意图常按「搜索」算、缺少打人红格；对方一回合走位获得视线后攻击，感觉「看得见却没预警」。

**候选**：

1. **见位即预警**（倾向）：格子上标了敌人（含 `?`）就给完整红格  
2. **严格迷雾**：无视线不标真位置，只留 `lastSeen`  
3. **弱化脊挡视线**：墙仍挡；中间高脊不再挡视线  

**暂定**：存疑；未改代码前以现行 `hasLoS` + 意图预告为准。

## 5. AI OC 首期实现口径

产品方向已经锁定，以下工程选择仍待原型数据决定：

| 议题 | 当前倾向 | 拍板条件 |
| --- | --- | --- |
| 回顾生成位置 | 异步云端；失败走本地模板 | 测出延迟、单局成本与离线需求 |
| 事件日志字段 | 在 `cabin-lab-v1` 旁新增叙事事件流，不直接拿遥测文本拼 Prompt | 完成 10 局样本并能稳定复述关键事实 |
| 记忆存储 | 先结构化 JSON + 摘要，不先上 ChromaDB | 单角色记忆量超过简单检索能力 |
| 后台日常频率 | 离线最多积累 3 条，不推进主线与数值 | 测试回访期待与内容重复率 |
| 情绪图 | 预设精选立绘；运行时生图后移 | 文字闭环和角色一致性先验收 |
| 玩家数据 | 默认最小采集，可导出/删除，不接外部生活数据 | 完成隐私说明与授权流程 |

在这些议题拍板前，可以实现事件 schema、模板回顾和事实校验；不要提前搭建复杂多 Agent、向量数据库或实时生图管线。

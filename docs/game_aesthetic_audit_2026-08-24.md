# 游戏内审美审查与整改清单（2026-08-24）

## 1. 目标与判断基线

本清单以正式 Godot 对局为第一优先级，地编工具和后台测试场景只在其视觉问题会流入正式游戏时处理。目标不是把素材继续堆进场景，而是让大地图、战斗房、UI 和镜头共同服务于同一个视觉概念：

- 80 年代电视节目包装；
- 绿色手工垫板上的纸盒微缩片场；
- KayKit 木地板作为房间统一尺度；
- 房间中的家具布局在大地图与战斗房之间保持身份连续；
- 玩法信息用图形、色彩和动画表达，避免调试式悬浮文字。

审查证据来自 1280×800 实际 Vulkan 截图，而不是只看节点树：

- `godot/artifacts/completion_00_home.png`
- `godot/artifacts/camera_house_default.png`
- `godot/artifacts/kenney_formal_room_occupied.png`
- `godot/artifacts/battle_room_context_full.png`
- `godot/artifacts/battle_room_context_world.png`
- `godot/artifacts/battle_room_context_living_override.png`

## 2. 本轮已经修复

### 2.1 战斗地板规格统一

- 战斗房不再使用白色厚方块作为可见地板。
- 正式复用大地图的 `floor_wood_large.gltf.glb` 与 `floor_wood_large_dark.gltf.glb`。
- 比例规则与大地图一致：模型基准宽度 4m，战斗中按 `BATTLE_CELL / 4.0` 缩放。
- 房间 footprint 内使用亮木板，外围玩法格使用暗木板，保留 6×6 战斗逻辑但能读出原房间轮廓。
- 每格仍保留不可见逻辑 `Surface`，不改变拾取、移动和高度判定。

### 2.2 清除 3D 调试文字

- 删除战斗格上的 `H1/H2`。
- 删除房间上方“某某房 · 当前房间”。
- 删除怪物头顶“怪/?”。
- 正式大地图 composer 已明确设置 `show_room_ids = false`、`show_summary_title = false`。

### 2.3 战斗提示图形化

- 敌方意图改为角色上方的小型彩色徽章。
- 移动路径由整格蓝色面板和“走1/走2”改为小型编号圆点。
- 攻击范围由整格文字面板改为红色警告圆点与四角标记。
- 普通移动范围不再常驻铺满青色角点，只在悬浮目标时显示；选中放置牌时仍显示完整可放区域。
- 家具顶部的逻辑站立面保留但默认隐藏。

### 2.4 战斗 UI 层级整理

- 行动力票据从右下角移到玩家与敌人状态栏之间。
- 回合结束按钮移到弃牌堆左侧，不再覆盖弃牌堆。
- 自动取景减少空背景安全边距，房间模型约放大 11%，旋转四角仍通过回归测试。

## 3. 正式游戏仍存在的问题

### P0：下一轮应优先解决

#### A. 非手调房间仍像“算法填充”

现象：同一种灯、盆栽、桌子或箱子会等距排成阵列；资产数量增加了，但缺少主次关系，像测试数据可视化。

解决：

1. 每个房间先选一个视觉焦点（床、沙发、餐桌、祭坛、舞台）。
2. 资产分为 `anchor / support / clutter / wall_bound` 四层，不允许 clutter 自己决定构图。
3. 相邻两格不得出现相同小道具；同模型整房默认最多出现两次。
4. 先生成可行走主通道，再在通道外布置家具。
5. 对齐关系只允许成组出现：餐桌配椅、沙发配茶几、床配床头柜，禁止全房等距对齐。
6. 生成后计算重复度、空洞度、门口遮挡和视觉焦点评分，不达标就重排该房，不重生成整张地图。

#### B. 大地图 footprint 与战斗房外壳仍不是同一形状

现象：亮/暗木板已经表现 1/3/5 格 footprint，但纸板墙仍包住整个矩形 6×6 战斗盘。玩家能认出主题，却不能一眼认出这是大地图上的 L3、T5 或长条房。

解决：

1. 从 `battle_room_context.footprint_cells` 生成战斗外轮廓边集合。
2. 只在 footprint 外边生成纸板墙；内部格线不建墙。
3. 逻辑战斗盘超出 footprint 的格子改成“片场后台”：深绿垫板、胶带标记和虚化暗区，不再继续铺暗木地板伪装成房间。
4. 房门沿用大地图的 entrance/connection 边，旋转房间时同步旋转。

#### C. 高低差资产缺少语义

现象：当前家具可以代替立方体，但系统仍可能把不适合站立的灯、盆栽或窄书架选成高度平台；“有模型”不等于“像可攀爬地形”。

解决：

1. 资产目录增加 `walkable_top`、`top_height`、`top_radius`、`climbable`。
2. 只有桌、柜、床、箱、台阶等白名单资产能成为 H1/H2。
3. H2 必须由楼梯、箱堆或两个相关资产构成，不允许把单个模型粗暴拉高。
4. 站立点使用资产本身轮廓和接触阴影表达，交互时才显示薄金边。

#### D. 大地图与战斗房的材质混用仍明显

现象：纸板墙、KayKit 木地板、Quaternius 家具和部分 2D 图标的明暗与饱和度不一致。

解决：

1. 建立运行时材质归一层，不修改原始资产：降低塑料高光，统一 roughness，加入轻微暖纸色乘色。
2. 所有正式房墙体只走纸板材质；砖墙只允许作为战斗中的柱、废墟或障碍物。
3. 家具保留主题色，但限制到“木棕、奶油黄、电视青、节目粉、警示金”五个主色族。
4. 用同一个主灯方向和接触阴影强度连接不同来源的资产。

### P1：完成 P0 后处理

#### E. 战斗 UI 与 3D 色彩竞争

- 卡牌的青/粉/黄饱和度远高于房间，悬浮时合理，静止时会抢走房间焦点。
- 行动力票据仍偏亮，应在非玩家操作阶段降低约 15% 亮度，轮到玩家时再点亮。
- 牌堆/弃牌堆背面体积偏大，可缩到当前 85%，把底部中心留给手牌弧线。
- 角色状态栏信息完整，但 720p 下小字和灰色 pips 对比偏低。

#### F. 大地图早期构图过小

- 开局房间很少时，相机仍为未来布局和 frontier 留出大量空间。
- 应根据“已揭示房间包围盒”取景，frontier 只贡献半格边距；新增房间的建造动画结束后再平滑扩框。
- frontier 的金色 `+` 方块仍接近编辑器标记，应替换为纸片门牌、节目锚点或闪烁电视信号。

#### G. 未揭示房间看起来像缺材质

- 当前深灰空台能表达未知，但也像加载失败。
- 建议覆盖半透明描图纸、纸箱盖或电视雪花遮罩；揭示时掀开/抽走，而不是从灰块瞬间变家具。

#### H. 角色与地面接触感不足

- 玩家和怪物脚下圆盘过厚、颜色过亮，模型像棋子而不是处在房间里。
- 圆盘应改成更薄的纸片圈；静止时低透明，选中/受击/目标锁定时再增强。
- 增加小范围 blob shadow 或 decals，确保脚、家具和地板接触一致。

#### I. 战斗镜头缺少事件构图

- 当前默认全景已更大，但攻击、受击、敌人揭示仍大多沿用同一个画幅。
- 攻击时短促推近目标 6%–10%，受击时叠轻微手持震动，动作结束恢复。
- 首次进入 5 格精英房，先给 0.6 秒房间全景，再切玩家/敌人中点；普通 1 格房不应使用同等级演出。

### P2：包装与后台场景

#### J. 首页控制区拥挤

- 视频主页和 80 年代标题方向正确，但下方按钮、种子输入、分辨率与退出同屏竞争。
- 正式首页只保留“开始/继续/新手教学”；分辨率、窗口、移轴和退出收进设置面板。
- 后台测试入口只在开发构建显示。

#### K. 后台测试场景仍是占位美术

- 横版测试：几何平台与空背景。
- 九宫格测试：纯色方块，没有纸片/电视节目语汇。
- 搜索房测试：盒子式原型，没有正式房间资产。

这些不应阻塞正式游戏，但如果后台测试会出现在公开试玩包里，需要加统一的“开发中/片场排练”包装，避免玩家误认为是正式完成度。

#### L. 字体层级不够稳定

- 展示字体适合标题和按钮，不应覆盖长说明。
- 正文字体在 1280×720 下不得小于 11px；灰字与深背景对比至少维持 4.5:1。
- 中文按钮宽度按最差字串预留，避免多语言替换后拥挤。

## 4. 每轮美术回归必须截图的状态

1. 首页：1280×720 与 1920×1080。
2. 大地图：只有 1 个房、已有 3 个房、已有 5 个房。
3. 房间摆放：长条 3 格旋转前后、L3 旋转前后、T5 旋转前后。
4. 普通战斗：自动生成房、手调 override 房各一张。
5. 精英战斗：默认镜头、旋转 90°、最大/最小缩放。
6. 卡牌：静止、悬浮、拖动箭头、可放/不可放目标。
7. 敌方意图：移动、攻击、多段攻击、未揭示。
8. 高低差：玩家站在 H1/H2 资产上，不能出现悬空或穿模。
9. 建造动画：开头、中段、完成后三帧。

## 5. 可量化验收线

- 正式 3D 场景中悬浮调试文字数量：0。
- 战斗默认镜头中房间占可用战场宽度：60%–82%；高度：55%–78%。
- UI、牌堆、按钮之间的像素重叠：0。
- 门前一个玩法格范围内的不可穿越装饰物：0。
- 相邻重复小道具：0；同模型同房默认不超过 2 个。
- 每房至少 1 个视觉焦点、1 条连续主通道、1 组语义家具组合。
- 手调 override 房进入战斗后，焦点家具、门方向和 footprint 三项全部可辨认。
- 旋转任意角度后，房间外轮廓、玩家、敌人和入口均在画面内。
- 1280×720 下所有正式玩法文字清晰可读，不依赖截图放大。

## 6. 推荐执行顺序

1. footprint 驱动战斗外壳，并把外围逻辑格改成绿色片场后台。
2. 给 PCG 资产增加语义层与构图评分，消除阵列式重复。
3. 增加高低差资产白名单和精确站立面数据。
4. 建立材质归一层和房间主题调色板。
5. 优化大地图早期取景、未知房遮罩和 frontier 图形。
6. 最后统一角色脚圈、事件镜头、首页设置层级和后台测试包装。
